SME CashFlow - plan.txt (system design and logic overview)
==========================================================
Version 2.0.0 (20 Oct 2026). Live app: https://smecashflow-two.vercel.app
A cash-flow forecasting app for Malaysian micro-businesses. BFM3130, Tutorial 1, Group 4.


1. SYSTEM DESIGN
----------------
  Phone / laptop browser
        |  opens the link (can be added to the phone home screen)
        v
  VERCEL (frontend)  - HTML pages, CSS and JavaScript; no server code, no build step
        |  login and data requests (HTTPS, Supabase REST API)
        v
  SUPABASE (backend)
    - Auth: email and password login
    - PostgreSQL database with Row Level Security (each user sees only their own rows)
    - Database functions and triggers for actions that must be all-or-nothing
    - Edge Function "ai-insights" (Deno/TypeScript) holding the secret Gemini key
        |  forecast numbers only
        v
  GOOGLE GEMINI API (gemini-3.5-flash-lite) - returns 3-4 cash-flow tips

Frontend files (top level of the repository):
  *.html                  one file per page (home, sign-up, login, dashboard, invoices,
                          expenses, import, scenarios, reports, team, settings, admin, 404)
  css/style.css           colours and layout
  js/cashflow.js          money, dates, the forecast and CSV reading (pure logic, tested)
  js/plans.js             plans, free trial, SST, demo business (tested)
  js/insights.js          what is sent to the AI, and the built-in backup tips (tested)
  js/db.js                every call to Supabase, in one place
  js/ui.js                menu, messages, safe HTML, chart, login check
  js/i18n.js, i18n-ms.js  English / Bahasa Melayu
  js/pages/*.js           one script per page
  tests/                  39 automatic tests
Backend files:
  supabase/schema.sql                      tables, security rules, functions (run first)
  supabase/upgrade_admin_ai.sql            v2.0: admins, live event log, admin functions
  supabase/functions/ai-insights/index.ts  v2.0: AI Edge Function


2. DATABASE
-----------
profiles       business name, location, current cash, plan, trial start/end, demo flag
               (created automatically at sign-up by a trigger)
invoices       customer, amount, due date, unpaid/paid, paid date
expenses       description, category, amount, first due date, repeats (none/weekly/monthly)
uploads        an uploaded CSV file (pending review / done)
import_rows    the rows of a CSV, waiting for the user to confirm them
team_invites   name, role, invite code (max 10, Premium)
app_events     the live log (sign-ups, logins, plan changes, invoices, uploads, AI requests)
admins         who may open the Admin Control Centre

Money is stored as whole sen (integers), so RM amounts are always exact.
Dates use Malaysia time (UTC+8).


3. MAIN LOGIC
-------------
3.1 Forecast (js/cashflow.js, buildForecast)
    Start with today's cash. For each day of the next 7, 30 or 90 days:
      + unpaid invoices due that day (overdue invoices are expected today)
      - expenses due that day (weekly and monthly ones repeat)
    The lowest balance is the "low point"; any day below RM0 is a shortfall and
    the dashboard shows a warning. Forecasts are estimates, not financial advice.

3.2 Scenarios (Premium)
    The same forecast again with "customers pay N days late" and/or "cut costs by N%",
    drawn next to the normal forecast.

3.3 CSV import with review
    The file is checked (max 256 KB, 200 rows). Rows wait in import_rows; the user
    ticks the ones to keep (possible duplicates start unticked). Only then does the
    database function accept_import() turn them into invoices and expenses.

3.4 Plans, 1-month free trial and SST
    Free RM0 (7-day forecast, 2 uploads a month), Basic RM19.90 (30 days, summaries),
    Premium RM39.90 (90 days, scenarios, detailed report, team).
    Premium starts with a 30-day free trial, once per account; only the database
    function start_premium_trial() can set the trial dates. 8% SST is added to paid
    plans and to the optional RM49 guided onboarding. Prototype: no payment is taken.

3.5 Mark invoice paid
    mark_invoice_paid() marks the invoice paid AND adds its amount to current cash in
    one step, so a double-click can never add the money twice.

3.6 AI advice (v2.0)
    1. The user taps "Ask AI" on the dashboard.
    2. The browser builds a summary of the forecast: numbers, dates and categories only
       (customer names become "Invoice"; no names, emails or bank details).
    3. The Edge Function checks the user is logged in, then calls Gemini with the key
       from Supabase Secrets and returns the tips (English or Bahasa Melayu).
    4. If the AI fails or takes over 30 seconds, ruleInsights() gives built-in tips
       instead, so the feature never breaks.
    5. Every request is recorded in the live log (answered by AI, or backup used).

3.7 Admin Control Centre (v2.0, admin.html)
    Ten sections: Overview (users, plans, revenue), System health (checked every
    30 s), Server, API monitor, AI & routing, Live log (every 5 s), Cyber security
    (11 live checks), Backend engineering, Code health (runs the 39 tests), Releases.
    Every admin function checks is_admin() inside the database; admin rights can only
    be given in the Supabase SQL Editor.

3.8 Languages
    Every sentence on screen goes through t(); js/i18n-ms.js holds the Malay version.
    A test fails if any sentence has no translation.


4. SECURITY
-----------
- Row Level Security on every table; logged-out visitors can read nothing.
- The database checks every amount, date, plan and text length again (27 rules).
- Passwords are handled by Supabase Auth (one-way hash); we never see them.
- Only the public Supabase key is in the app; the Gemini key stays on the server.
- Everything users type is escaped before it is shown (blocks script injection).
- HTTPS with HSTS, Content Security Policy and other security headers (vercel.json).


5. ASSUMPTIONS AND LIMITS (prototype)
-------------------------------------
- No real payments: changing plan is free and instant.
- CSV import only; PDF statements and receipt scanning are a later phase.
- No payment reminders, emails or SMS yet; team members cannot log in yet.
- Free plans: Supabase pauses after about a week of no use; Gemini has daily limits.
- Overdue invoices are assumed to be paid today in the forecast.
